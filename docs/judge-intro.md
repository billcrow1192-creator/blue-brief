# BLUE BRIEF｜審査員向け60秒説明

## 問い

海の情報を小さくしても、「判断に必要な意味」は残せるか。

海底センサーの情報は、そのままでは大きすぎます。しかし短くしすぎると「なぜ怪しいか」が消え、全部送ると回線が詰まります。BLUE BRIEFは、情報の出し方だけを変えたとき、現場の判断がどう変わるかを、同じ合成条件で比べるシミュレーターです。

## 一言でいうと

海底センサーの情報を、人の判断につなぐ練習用システムです。

操作するのは海そのものではなく、「誰に、何を、どこまで伝えるか」です。

## 3つの介入

- A：異常ラベルだけを送る。軽いが、理由や機器故障が消える
- B：詳細を常に送る。詳しいが、回線が詰まり重要情報が遅れる
- C：判断に必要な意味を短く送り、必要時だけ詳細を加える

## 観測する連鎖

海の観測 → 情報の要約 → 理由の消失／通信の渋滞 → 5職種の判断 → 信頼・反応・港湾負荷の変化

面白さは、情報が多いほど良いとは限らないことです。同じ出来事でも、自治体、港湾、漁業、救助、観測運用では必要な情報が違います。利用者は5職種へA/B/Cを割り当て、何が壊れるかを予測してから、同一seedの結果と判断根拠を比較します。

## 現在の実装境界

現在は96 tickの決定論的状態遷移に加え、5役割×2ラウンドのLLMランナーと監査ログを実装しています。ただし、記録済みLLM実験は1条件1回であり、架空湾・合成データだけを使った研究用プロトタイプです。公式警報の代替、実船の識別、実座標の利用は行いません。実務環境での有効性・安全性は今後の検証項目です。
