# BLUE BRIEF

**AIエージェント社会シミュレーション・ハッカソン Vol.2「メタ安全保障」提出作品**  
参加者番号: `0156` / 提出者: `HiroPa`

海洋情報の量と組織判断の質を同時に検証する、意思決定リハーサル用プロトタイプです。

## 中心仮説

帯域制約下では、情報が少なすぎても多すぎても意思決定が壊れます。

- A: 異常ラベルのみ。通信は軽いが、不確実性と機器状態が失われる
- B: 詳細を常時送信。意味は残るが、通信逼迫時に重要情報が遅れる
- C: 最小安全パケットを常送し、不一致時だけ短い根拠データを取得する

同じ外生イベントとseedでA/B/Cを実行し、誤警報、真の異常への反応時間、情報源の信頼、港湾待機、通信量、回収見込みを比較します。

## 実行

必要環境: Node.js 22.13以上

```bash
npm ci && npm run dev
```

表示されたローカルURLをブラウザで開き、最初に「60秒ガイド」、次に「LLM実験」を確認してください。APIキーなしでも、記録済みLLM実行と決定論シミュレーターを操作できます。

本番ビルドは `npm run build` です。

## 実装

- 初期画面に、問い・介入・連鎖・操作手順・実装境界を示す「審査員向け60秒ガイド」
- 自治体・港湾・漁業・救助・観測運用を独立コンテキストで動かす5役割LLMランナー
- Round 1の判断・宛先付きメッセージを共有bulletinとしてRound 2へ渡す2段階オーケストレーション
- Codex環境で実行した1エピソードの生ログと、監査専用LLMによる限定的な創発候補の評価
- 96 tick、1 tick 5分の決定論的状態遷移
- 12センサー、2ゲートウェイ、自治体・港湾・漁業・救助・観測運用
- seed固定による再現
- 情報送信方式A/B/Cの同一条件比較
- 毎日変わる合成条件で、5職種にA/B/Cを割り当てる「今日の4分演習」
- 役割×方式の探索履歴をブラウザの端末内だけに保存
- 海図上の合成センサーノードをタップして状態を確認
- 監査JSONと比較CSVのブラウザ出力
- 架空候補点の配置・回収に関する相対評価

シミュレーション本体は `lib/simulation.ts`、操作画面は `app/page.tsx` です。

## 境界

- 架空湾・合成データのみを使用する
- 公式警報を発令・代替しない
- 実在船、船籍、敵意を識別しない
- 実在する防衛・警備機関へ自動通知しない
- 実配備座標、実価格、100%回収を主張しない
- 既存のS-net、N-net、AODASを置き換えない
- 日次演習の履歴は端末内記録であり、実務能力や現実の安全性を採点しない
- 物理・通信環境は決定論的。LLMは組織判断だけを担当する
- 記録済みLLM実験は1条件・1回であり、再現性・因果性・実環境性能を示さない
- 自然言語メッセージの配送はオーケストレータ経由で、自律形成された通信網ではない

## LLMエージェント実験

記録済み実行の検証：

```bash
npm run agents:verify
```

OpenAI Responses APIで再実行：

```bash
OPENAI_API_KEY=... OPENAI_MODEL=gpt-5.6 npm run agents:run
```

モデルは `OPENAI_MODEL` で差し替えできます。Structured Outputsを使い、API側の保存は `store: false` にしています。

`OPENAI_API_KEY` は環境変数からのみ読み込みます。リポジトリには認証情報を含めていません。
